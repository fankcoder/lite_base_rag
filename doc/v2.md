3. 关键代码实现（全部已写入文件并验证可运行）
✅ tracer middleware（FastAPI）— src/tracing/middleware.py
已在上面输出，功能：

自动读/生成 x-trace-id、x-session-id
contextvars 传播到下游
请求开始写 query_request，结束写 query_complete（带 status_code + duration）
response header 回填 x-trace-id
✅ markitdown adapter — src/parser/unified_parser.py
核心设计：

MarkItDownAdapter.available 做 lazy import 探测：未安装 markitdown 时自动降级，不报错
parse_document() 流程：markitdown → markdown → markdown_to_sections()；失败 → _legacy_parse()（md/pdf/ppt 旧解析器）→ 拼 markdown → 同样结构化
输出 ParsedDocument{title, sections[]}，同时 parse() 兼容旧接口返回 List[DocumentChunk]
✅ chunker v2（结构化）— src/chunking/chunker.py
核心特性：

严格不跨 section
每个 chunk 正文前自动注入 # main_title\n## section_title\n\n…，防语义漂移
_split_into_blocks() 识别 code fence（```）和 list，不把它们切断
超长段落自动 _sliding_text()（按换行/句号友好切分，带 overlap）
小于 min_tokens 的尾部 chunk 自动与前一个合并
fallback：无标题文档走 sliding window
✅ skill loader — src/skills/（loader + registry + runtime）
manifest.json 声明式；importlib.util.spec_from_file_location 动态加载 entry
entry 约定 def run(ctx) -> SkillResult
SkillRegistry.install_from_manifest() 把 manifest + 可选代码写入 skills/installed/<name>/
SkillRuntime.execute() 统一依赖注入（rag/index/embedder/tracer/vector_store），并自带 tracing span
内置示例 skills/knowledge_search.py（RAG 检索 skill）
4. 风险分析
风险点	说明	应对方案
性能风险	TracingMiddleware 和每个 span 有少量 overhead；structured chunking 比固定切片略慢	span 计时已在纳秒级；异步线程池写 trace（默认 2 线程），不阻塞主链路；可通过 TRACING_ENABLED=false 一键关闭
Embedding 计算成本	StructuredChunker 产出更多短 chunk（原 1→多 section）导致 embedding 次数增加	chunk 会自动合并小于 min_tokens 的相邻节；tokens 字段已写入 metadata，后续可做 batch & cache；milvus lite 下万级文档无压力
Trace 存储压力	每次 query 产生 5~10 个事件，QPS 高时磁盘/内存增长快	默认 InMemory 环形缓冲 200k 条（TRACING_MAX_EVENTS）；同时输出 JSON 结构化日志行（RAG_TRACE {...}），可直接接 Loki 做外部长期存储；生产换 ES/CK adapter 即可
Chunk 质量波动	MarkItDown 对扫描版 PDF / 复杂表格输出质量不稳定	fallback 机制：markitdown 失败 → 原 pdfplumber+PyMuPDF 流程；解析器来源写入 metadata（parser_used 字段）便于排查；code block 识别依赖 ``` fence，扫描件无 markdown 结构自动 fallback sliding window
Skill runtime 安全	entry_code 可执行任意 Python（manifest 的 permissions 目前只声明未强制）	默认 permissions=["local_read"]；safe_run() 预留扩展点，可加沙箱（subprocess + 资源限制）；SKILLS_ALLOW_UNTRUSTED=false 可在网关层拦截非白名单代码；建议生产对 entry 代码做签名/人工审核
旧接口兼容性	parse_file() 签名变化、vector schema 新增字段	parse_file(use_unified=True) 默认走新路径；VectorStoreLite 用 JSON 无 schema，新字段自动兼容；Milvus server 模式可能需要 migrate schema（已在 main_title/section_title/tokens 字段设计为可选）
